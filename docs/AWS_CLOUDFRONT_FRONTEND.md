> # GrantThrive: AWS CloudFront Frontend Deployment Guide

This guide provides a detailed, step-by-step plan for deploying the GrantThrive React frontend to a highly available, scalable, and performant environment using AWS S3 for hosting and AWS CloudFront as a Content Delivery Network (CDN).

This architecture ensures fast load times for users globally and correctly handles the client-side routing of a Single-Page Application (SPA).

---

## 1. Core Concepts: S3 + CloudFront for a React SPA

*   **Amazon S3 (Simple Storage Service):** We use an S3 bucket to store the static output (`HTML`, `CSS`, `JavaScript`, image files) generated by the `pnpm build` command. We configure this bucket for static website hosting.
*   **Amazon CloudFront:** This is a global CDN that caches your content in edge locations around the world, closer to your users. It provides two key benefits:
    1.  **Performance:** Users fetch assets from a nearby edge location instead of the S3 bucket's specific region, dramatically reducing latency.
    2.  **SPA Routing:** CloudFront can be configured to handle the "404 Not Found" errors that occur when a user directly accesses a URL like `/app/grants/123`. Instead of returning a real 404, CloudFront serves the `index.html` file, allowing the React Router to take over and render the correct page.

## 2. Building the Frontend for Production

First, you need to create a production-ready build of the React application on your **local machine**.

### Step 1: Configure Production Environment

1.  Navigate to the `grantthrive-frontend` directory.
2.  Create a production environment file from the example:

    ```bash
    cp .env.production.example .env.production
    ```

3.  Edit the new `.env.production` file:

    ```bash
    nano .env.production
    ```

4.  Set `VITE_API_URL` to the public HTTPS URL of your deployed backend API.

    ```ini
    # .env.production
    VITE_API_URL="https://api.yourdomain.com/api"
    ```

### Step 2: Run the Build Command

Install dependencies and run the build script using `pnpm`.

```bash
pnpm install
pnpm build
```

This process compiles and optimizes your React application and places all the static assets into a `dist/` directory.

## 3. S3 Bucket Setup for Static Hosting

Next, create and configure the S3 bucket that will store your application files.

### Step 1: Create the S3 Bucket

1.  Navigate to the [AWS S3 Console](https://console.aws.amazon.com/s3/).
2.  Click **Create bucket**.
3.  **Bucket name:** It is a good practice to name the bucket after your domain, e.g., `app.yourdomain.com`.
4.  **AWS Region:** Choose a region.
5.  **Block Public Access settings for this bucket:** **Uncheck** the "Block all public access" box. You must acknowledge the warning that the bucket will be made public.
6.  Click **Create bucket**.

### Step 2: Enable Static Website Hosting

1.  Go to your newly created bucket and click on the **Properties** tab.
2.  Scroll down to **Static website hosting** and click **Edit**.
3.  Select **Enable**.
4.  **Hosting type:** `Host a static website`.
5.  **Index document:** `index.html`
6.  **Error document:** `index.html` (This is a fallback, but the main SPA routing will be handled by CloudFront).
7.  Click **Save changes**.

### Step 3: Apply a Public Read-Only Bucket Policy

1.  Go to the **Permissions** tab of your bucket.
2.  Under **Bucket policy**, click **Edit**.
3.  Paste the following JSON policy, replacing `app.yourdomain.com` with your actual bucket name.

    ```json
    {
        "Version": "2012-10-17",
        "Statement": [
            {
                "Sid": "PublicReadGetObject",
                "Effect": "Allow",
                "Principal": "*",
                "Action": "s3:GetObject",
                "Resource": "arn:aws:s3:::app.yourdomain.com/*"
            }
        ]
    }
    ```

4.  Click **Save changes**.

### Step 4: Upload Build Files to S3

Upload the contents of your local `dist/` directory to the S3 bucket.

```bash
# Navigate to your grantthrive-frontend directory on your local machine

# Sync the dist folder with your S3 bucket
aws s3 sync ./dist s3://app.yourdomain.com --delete
```

> The `--delete` flag is useful for removing old files from the bucket that are no longer in your build.

## 4. CloudFront Distribution for SPA

This is the final and most important piece for a production frontend.

### Step 1: Create the CloudFront Distribution

1.  Navigate to the [AWS CloudFront Console](https://console.aws.amazon.com/cloudfront/).
2.  Click **Create distribution**.
3.  **Origin domain:** Select your S3 bucket from the dropdown list. It will appear as something like `app.yourdomain.com.s3.amazonaws.com`.
4.  **Viewer > Viewer protocol policy:** Select **Redirect HTTP to HTTPS**.
5.  **Settings > Alternate domain name (CNAME):** Enter your frontend domain (e.g., `app.yourdomain.com`).
6.  **Custom SSL certificate:** Select the SSL certificate for your domain. You can request a free one from **AWS Certificate Manager (ACM)** in the `us-east-1` region (required for CloudFront).
7.  **Default root object:** Enter `index.html`.
8.  Click **Create distribution**.

### Step 2: Configure Custom Error Pages for SPA Routing

This step is **essential** for ensuring your React Router works correctly.

1.  Wait for your distribution to finish deploying.
2.  Go to the **Error Pages** tab for your distribution.
3.  Click **Create Custom Error Response**.
4.  Configure a rule for **403: Forbidden**:
    *   **HTTP Error Code:** `403: Forbidden`
    *   **Customize Error Response:** `Yes`
    *   **Response Page Path:** `/index.html`
    *   **HTTP Response Code:** `200: OK`
5.  Click **Create**.
6.  Create another rule for **404: Not Found** with the exact same settings:
    *   **HTTP Error Code:** `404: Not Found`
    *   **Customize Error Response:** `Yes`
    *   **Response Page Path:** `/index.html`
    *   **HTTP Response Code:** `200: OK`

This configuration tells CloudFront: "If you can't find a specific file (like `/app/grants/123`), don't return a 404 error. Instead, return the `index.html` file with a `200 OK` status." The browser will then load your React app, which will read the URL and render the correct client-side route.

---

## 5. DNS Configuration

Finally, point your domain to the CloudFront distribution.

1.  Go to your DNS provider (e.g., Amazon Route 53).
2.  Create a new record for your frontend domain (`app.yourdomain.com`).
3.  **Record Type:** `A`
4.  **Value/Route traffic to:** Select **Alias** and choose your CloudFront distribution from the list.

After DNS propagates, your GrantThrive frontend will be live, globally distributed, and fully functional at `https://app.yourdomain.com`.
